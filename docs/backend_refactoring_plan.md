# План рефакторинга Backend API (Завершен ✅)

В результате проведения большого рефакторинга бэкенда, серверная часть была полностью переведена от монолитной структуры (где вся бизнес-логика находилась в `cmd/server/`) к модульной архитектуре (Domain-driven / Feature-based) в `internal/features/`.

## Состояние кодовой базы после рефакторинга

Все 6 фаз рефакторинга завершены:

1. **`internal/core/auth` & `internal/features/auth`** — аутентификация пользователя, сессии, логин по OTP коду и управление пользователями.
2. **`internal/features/comments`** — комментарии к блокам письма, резолюция комментариев, фильтрация и блокирующие комментарии.
3. **`internal/features/ai`** — интеграция с OpenAI API, обработка промптов, кэширование результатов анализа, логгирование вызовов AI и SSE-стриминг результатов.
4. **`internal/features/emails`** — центральный домен: управление версиями писем, area approvals (согласование зон), редактируемые поля, генерация HTML, история событий и активность по письмам.
5. **`internal/features/boards`** — управление досками статусных этапов, настройка этапов и конфигурация прав/согласований.
6. **`cmd/server`** — легкая точка входа (`main.go`), не содержащая бизнес-логики. Отвечает только за считывание конфигурации (`.env`), инициализацию базы данных, логгеров и монтирование (wire-up) роутов из всех `internal/features/*`.
